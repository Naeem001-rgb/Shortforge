# ShortForge shared contract v1

Engine: http://127.0.0.1:8787. Dashboard: http://localhost:5173. JSON except multipart uploads, file responses and SSE. Errors use FastAPI `{detail: string}`. IDs are UUID strings. Times ISO8601 UTC. All paths saved in SQLite are relative to data directory. No absolute paths from clients.

YouTube services: see [YOUTUBE.md](YOUTUBE.md) for connection, upload, progress and recovery routes. Channel connection Settings remain available, but the previous editor's Publish to YouTube/Publish kit UI was removed and Concat has no publishing handoff. OAuth credentials and upload sessions never appear in public responses.

**There is no rights or licence gate anywhere in this API.** Supported clip operations do not deny access because of `license_status`. `license_status`, `permission_note`, `credit_target` and `credit_snippet` are recorded metadata that the dashboard displays; nothing refuses work because of them. Downloads, transcription, editing and export all proceed for `unknown` clips. Do not add a gate to satisfy a doc that describes one — see [AGENT.md](../../AGENT.md#2-preserve-these-behaviours).

## Core exports (engine/core)
`engine.core.app:app` FastAPI application. It always includes `engine.core.routes.router`, then optionally includes, in order, `engine.core.concat`, `engine.core.youtube_auth`, `engine.core.youtube_uploads`, `engine.core.scout_routes` and `engine.ai.routes`. A router module that is absent is skipped, but a missing dependency *inside* a router that does exist is raised rather than silently swallowed.
`engine.core.db`: `DATA_DIR: Path`, `connect()` context manager yields sqlite3.Connection with Row row_factory, `get_clip(id)->dict` raises HTTPException(404), `add_asset(clip_id, kind, path)->dict`, `get_asset(id)->dict`, `get_settings()->dict` (real values for internal use), `save_script(clip_id, original_text, rewritten_text)->dict`, `new_job(type, clip_id, *, unique_active=False)->dict`, `update_job(id, **fields)`, `require_editable(clip_id)->dict`. Schema initializes when connect used. Paths accepted by add_asset are Paths under DATA_DIR. Asset returned has url `/api/assets/{id}`.

`require_editable(clip_id)` is an **existence check only**: it returns `get_clip(clip_id)`, so the single failure it can raise is 404 for a clip that does not exist. It never inspects `license_status` and never returns 403. The name is historical; it is kept as a shared hook the media routes already call, and it must never be changed to promote an unknown source to owned or to bypass asset ownership.

## Entities
Clip: id, video_id(nullable), url, channel_name, channel_handle, title, description, likes(nullable integer), views(nullable integer), credit_target, credit_snippet, license_status: unknown|cc_by|permission|owned, permission_note, thumbnail_url, workflow_status: collected|downloaded|transcribed|editing|exported|archived, discovery_mode: credits|narrated|manual|upload|project, created_at, published_at(nullable). license_status and workflow_status are constrained by SQLite CHECK; discovery_mode is a plain column, so treat the list as the values actually written (extension scouting writes credits/narrated, uploads write upload, legacy records may retain project, and other current imports default to manual).
Clip detail additionally includes assets: Asset[], script: Script|null, transcript: {text, words:[{word,start,end}]}|null.
Asset: id, clip_id(nullable for voice references), kind, path, url, created_at. kind is a plain string, not an enum. Current acquisition/voice paths write source|voiceover|reference; export and other roles may remain in historical records. Historical records may contain media roles written by the removed editor, so clients must tolerate unrecognised kinds. Concat project media is stored separately under `data/concat/`, not through the removed `/api/editor/{id}/media` route.
Job: id, type, clip_id, status: queued|running|completed|failed, progress 0..100, error|null, result: object|null.
Script: clip_id, original_text, rewritten_text, words_original, words_rewritten.

## Core API
GET /api/health -> {status:'ok', version:'0.1.0', runtime:{...}, tools:{ffmpeg:bool,yt_dlp:bool,whisper:bool,piper:bool,espeak:bool}}. `runtime` is `engine.core.runtime.status()` — an advisory report on the local Python/GPU runtime, not part of the stable contract.
GET /api/clips -> {clips:Clip[]}. Optional query: `q` (matches title/description/channel_name/credit_target), `license_status` and `workflow_status` (any entity value, or `all` for no filter; anything else is 422), `sort` in date|created_at|newest|views|likes|title (default date; anything else is 422).
`GET /api/clips` also returns `ETag` and `Cache-Control: private, no-cache`. A matching `If-None-Match` receives an empty `304`; normal responses retain the complete `{clips:Clip[]}` shape for existing clients. Dashboard pagination is client-side (50 per page), with search/sort over the complete response.
POST /api/clips {clips: partial Clip[]} -> {clips:Clip[],added:number}; accepts URL-only YouTube/Instagram Reel import (canonicalize, validate ID); all new external clips license_status=unknown regardless of client; API enrichment can promote CC. Don't auto-seed database.

GET /api/clips/{id} -> Clip detail
GET /api/clips/{id}/thumbnail -> cached JPEG for Instagram Reels. Instagram Clip responses expose this local thumbnail_url even for older imports with no poster; SQLite retains the supplied CDN URL. Uses existing source footage, otherwise fetches the supplied cover or recovers missing/expired covers through metadata-only yt-dlp. CDN images are bounded, decoded and saved locally; unavailable covers return 404 with no-store. YouTube thumbnail URLs are unchanged. Reimporting an existing Reel may refresh its supplied cover without duplicating the clip.
PATCH /api/clips/{id} {title?, license_status?:'permission'|'unknown', permission_note?, workflow_status?} -> Clip. Permission requires nonempty note. Client cannot claim cc_by or owned.
DELETE /api/clips/{id} -> {ok:true}. Removes the clip, its cascaded jobs/scripts/transcript/assets, and the media files it owns (source, voiceover + `.timing.json`, export + `.ass`) so disk space is reclaimed. Voice-clone `reference` recordings are owned by a voice profile and are never deleted here. Every path is re-resolved through the data-folder guard, so a tampered asset row cannot delete files outside `data/`. Empty per-clip folders are pruned.
POST /api/clips/delete-bulk {ids:string[]} (1-200, de-duplicated) -> {deleted:string[],missing:string[]}. Deletes each existing clip and reports ids that were already gone; a missing id never aborts the rest. Empty list or unknown fields are rejected.
POST /api/upload multipart `file`, `title` optional -> Clip (license owned; max 500 MB video). Local probing/normalization admits ordinary media containers only; network/local-file manifests disguised as footage are rejected.
POST /api/clips/{id}/enrich -> Clip (YouTube free key required)
POST /api/clips/{id}/download -> Job (background yt-dlp). Library and Studio atomically share an existing queued/running download; only the claimant executes it. Never consults rights — any existing clip can be downloaded.
POST /api/clips/{id}/transcribe {model?:'base'|'small'} -> Job (clip must exist, source asset required; installed local model only, no silent download)
POST /api/clips/{id}/extract-script {provider?:'auto'|'gemini',replace_existing?:false} -> Job type 'extract-script'. Text extraction is available to all Library clips. Auto reuses saved text, then tries original-language public YouTube captions or an existing authorized local source with installed Whisper. No video download or cloud calls in Auto. Gemini explicitly sends the public YouTube URL to the configured model for verbatim transcription. Result: {text,words,source,language,word_count,original_updated}. Persists transcript and scripts.original_text together, preserving rewritten text and concurrent edits. replace_existing:true bypasses saved text only for an explicit re-extraction. Unknown/missing speech fails honestly; never derive an original script from title/description.
Concurrent transcription or script-extraction requests for the same clip/type atomically allow one active job; duplicates return HTTP 409. A failed/completed job permits a later request.
PUT /api/clips/{id}/transcript {text,words:[{word,start,end}]} -> {text,words}
GET /api/jobs/{id} -> Job
GET /api/jobs/{id}/events -> SSE `data: {Job}\n\n` until completed/failed.
GET /api/assets/{id} -> FileResponse; resolve only within DATA_DIR.
GET /api/settings -> {gemini_model, youtube_api_key_set, gemini_api_key_set, elevenlabs_api_key_set, niche,language, min_likes,min_views,target_count,scout_mode,tts_provider,piper_model,whisper_model,clone_model_path,clone_vocab_path,clone_config_path}; NEVER returns API key values. The non-secret keys are exactly `engine.core.db.DEFAULT_SETTINGS`; each secret in `SECRET_SETTINGS` is reported only as a `{name}_set` boolean.
PUT /api/settings partial settings + gemini_api_key?, youtube_api_key?, elevenlabs_api_key? -> same masked settings. Unknown setting keys rejected.

`POST /api/projects`, `PATCH|DELETE /api/projects/{id}`, `POST /api/projects/{id}/duplicate`, `POST /api/projects/{id}/exports` and `POST /api/seo` were removed with the custom browser-editor workflow and return 404. ## AI API (engine/ai)
POST /api/rewrite {clip_id, text, mode?:'rewrite'|'original', topic?:string} -> {original_text,rewritten_text,words_original,words_rewritten,within_tolerance,exact_word_count?,attempts}. Gemini configurable model default gemini-3.8-flash, missing key is actionable 400. Script rewriting is available to all Library references independently of footage permissions. Rewrite preserves original language, tone, perspective, context, fact sequence, names/numbers/qualifiers and hook/payoff, targets the exact whitespace word count, retries max twice, and retains the closest draft without padding or truncation. Semantic preservation is instructed, not guaranteed. Original mode separately writes from topic/title/description, not a transcription.
PUT /api/scripts/{clip_id} {original_text,rewritten_text} -> Script
GET /api/voices -> {voices:[{id,name,provider,language,description,available,cloned}],providers:[{id,name,available,note}]}
POST /api/tts {clip_id,text,provider:'piper'|'edge'|'elevenlabs'|'clone'|'espeak',voice_id,speed:0.7..1.2,pitch?:-50..50} -> Job. Only background generation. Pitch is Edge-only: a nonzero pitch with any other provider is rejected with 400, not silently ignored. No model installs. Re-align voice if whisper installed, otherwise explicit timing approximation label. Do not reuse old transcript timing for new voice.
POST /api/voices/clone multipart file, name, consent ('true'), reference_text optional -> {id,name,provider:'clone',language,description,available,cloned:true}. Stores reference and consent for future local Chatterbox / Chatterbox Nano usage. Report unavailable until model dependencies/local checkpoint configured. Never pretend profile creation trained a model.
DELETE /api/voices/{id} -> {ok:true}

## Concat Studio API (engine/core)

The custom editor and its `/api/editor/*`, `/api/editor-capabilities`, `/api/presets`, `/api/captions/detect` and `/api/export` routes were removed. Do not build new clients against those routes. Concat uses its own native project format and renderer; no WebCodecs exporter remains in the dashboard.

GET /api/studio/capabilities -> {available:boolean, editor:'Concat', version?:string, message:string}. Reports native Concat readiness. Normal project setup automatically downloads and verifies the pinned runtime on supported platforms; this read-only endpoint does not install software.

POST /api/studio/open {clip_id?:string|null} -> Job type `studio-open`. Omitting `clip_id` opens Concat independently. A supplied id must identify an existing Library video; missing ids return 404, invalid ids or extra fields return 422, and unavailable runtimes return 503 before downloading media. Clients cannot choose an executable or arbitrary source path. Concurrent queued/running opens for the same clip reuse one job.

Poll GET /api/jobs/{id}. A completed job has result `{editor:'Concat',clip_id:string|null,title:string,project_created:boolean,project_path:string|null,opened:true}`. `project_path` identifies the saved native project, or is null for an independent Studio launch. The dashboard stays in its current tab and displays launch status; Concat opens on the local engine's desktop. A failed job carries an actionable `error` and preserves the Library video and saved edit.

For a first Library open, source footage is acquired through the shared download claim. If another request owns acquisition, Studio waits outside database transactions for up to 30 minutes and revalidates the completed source; a timeout leaves the owner running. The footage is then copied under `data/concat/projects/<clip-id>/media/`, and imported onto a 1080×1920, 30 fps Concat timeline. The project is saved and closed in a staging folder before becoming `data/concat/projects/<clip-id>/edit/`. An existing `concat.json` is reopened without reimporting or resetting cuts. Library deletion does not delete this separate project or media copy; old custom-editor timelines are not automatically migrated.

The `/api/studio/browser/*` HTTP and WebSocket routes were removed. The open-job result no longer contains a streaming URL or session id. Closing the ShortForge browser tab does not close Concat's native window.

Concat's native file chooser and export controls operate on the local computer. ShortForge does not relay exports into browser downloads. This is a local single-user desktop workflow requiring a graphical session, not a remote editor service. See [Concat setup and verification](../../docs/CONCAT.md).

## SQLite schema ownership
Core owns schema: clips entity above; jobs(id,type,clip_id,status,progress REAL,error,result JSON); scripts(clip_id PRIMARY KEY,original_text,rewritten_text,words_original,words_rewritten); assets(id,clip_id,kind,path,created_at); editor_projects(clip_id PRIMARY KEY,project JSON,saved_at) — retained legacy timeline data from the removed editor; current Concat edits are separate files; settings(key PRIMARY KEY,value JSON); transcripts(clip_id PRIMARY KEY,text,words JSON); voices(id PRIMARY KEY,name,reference_asset_id,reference_text,consent,created_at). Every clip_id is `REFERENCES clips(id) ON DELETE CASCADE` and foreign keys are enabled, so deleting a clip removes its jobs, script, transcript, assets and saved timeline. Indexes: assets(clip_id,created_at), clips(created_at). Agent AI may access connect using this schema.

## Extension
### Multi-platform scouting (October 2026)
External imports accept YouTube videos and Instagram `/reel/{shortcode}/` links. YouTube keeps its existing 11-character `video_id`; Instagram uses `ig:{shortcode}` to avoid cross-platform collisions. The canonical URL determines the platform. Instagram never uses YouTube enrichment or thumbnails.

Scout settings add `sourceUrl` (empty = current Shorts/Reels tab; otherwise a YouTube channel or Instagram account), `captionFilter` (`off`, `brief-only`, or opt-in `small-text-no-speech`, default `brief-only`), and `maxCaptionSeconds` (default 3, range 0–10). Likes and views remain user-editable nonnegative whole-number minimums; 0 disables that count requirement. Account scouting visits only links collected from that account's Shorts/Reels grid and stops when exhausted; it never continues into recommendations. Existing stored settings migrate with these defaults.

`POST /api/scout/caption-check {url, max_caption_seconds:3}` returns a standard Job with no Library clip created (`clip_id` is null). The engine downloads a temporary public video and runs local OCR across its full duration. `GET /api/jobs/{id}` polls it. Completed result: `{video_id,url,status:'clear'|'brief'|'persistent'|'unknown',duration,caption_seconds,coverage,frames_scanned,interval,reason}`. Persistent means detected on-screen text exceeds the chosen total seconds. This is a sampled estimate of visible text, not a guarantee of caption absence. Missing OCR/download/read failures must never pass the filter. Temporary media is deleted. Only one check runs at a time: a second request while one is in flight is 409, so the extension must finish or cancel the first. `POST /api/scout/caption-check/{job_id}/cancel` -> the Job; cancels only Scout checks (404 for any other job type) and waits briefly for the worker to delete its files and free the slot before answering, so a new check can safely follow. Unavailable dependencies return an actionable error. No paid services, authentication bypass, or browser-cookie extraction.

Optional request `policy:'small-text-no-speech'` (default `brief-only`) enables the small-Chinese-text exception AND local speech detection. Ignore only short, small OCR annotations: at most 12 alphanumeric characters total per frame, at least 80% Han characters, at most 2 text boxes, each no more than 6% of frame height / 40% of frame width, combined area at most 3% of the frame. Other text still counts against `max_caption_seconds`. This is a size/amount/script heuristic, not an aesthetic judgement of “modern” captions or definitive language identification. The whole audio track must be checked by the installed local VAD; detected speech, missing audio coverage, or unavailable analysis cannot pass. A verified video with no audio stream can pass. Music may cause conservative false rejections and quiet speech may be missed.

Jobs/results echo `policy`; the opt-in result adds `small_text_seconds`, `speech_status:'absent'|'present'|'unknown'`, `speech_seconds` (detected segments), `speech_analysis_duration`, and `speech_model`. `speech_analysis_duration` covers the video's duration (including the verified no-audio case). Present speech yields `status:'speech'`; absent speech with clear/brief remaining captions can pass. The extension binds each job ticket to policy, video, session, and seconds allowance and verifies these fields before saving. Legacy brief-only results may omit policy; opt-in results must explicitly echo it. No model downloads happen during scouting: explicit setup installs a small pinned free speech model locally.

For `small-text-no-speech`, a present or unverifiable speech result can finish before OCR. Such results retain `caption_seconds:null`, `coverage:null`, `small_text_seconds:null` and `frames_scanned:0`; they never imply captions were checked or permit the clip to pass.

Content-worker protocol: `prepareScan {clip}` returns `{running,captionJobId?,skipCaptionCheck?}` after metadata/duplicate checks; `captionStatus {jobId}` returns `{running,job}`; content polls outside the worker's serial message queue, then sends `scan {clip,captionJobId?}`. The worker verifies completed job identity and result before matching. Pausing must remain responsive during analysis. `hello`/`run` supply the session source URL; account queue state stays in session storage across same-origin navigations.

Manifest V3. Built dist directory loaded unpacked. Popup modes are `any` (the default for new settings — see below), `narrated`, `credits`, `auto` and `credits-any`; `narrated` and `credits` select count-qualified candidates, and for those two credits and keywords are not required. No mode verifies narration or identifies AI voices; the separate small-text/no-speech filter screens for detected speech of any kind. Optional 'auto' starts credits and switches after 30 misses. Unknown likes/views skip only when the corresponding minimum is positive; zero disables that count requirement. Explicit mode overrides saved Auto phase. Changing mode or count limits allows skipped videos to be checked again; matched videos remain deduplicated. Popup shows last-scan counts and decision, including skips. Human-paced 4–9 sec, max 500, pause on challenges. Never stealth or social actions. Posts bulk to /api/clips. Popup state from chrome.storage.local. All selectors in selectors.ts. Parser unit tests with Node assert.

The additional `mode:'credits-any'` preset requires attribution plus the user's likes/views minimums and always normalizes `captionFilter:'off'`, including restored storage. It accepts captions and voiceover without OCR or speech checks, never falls back to uncredited candidates, and saves `discovery_mode:'credits'`. Other modes (`narrated`, `credits`, `auto`) remain available with their existing behavior and independently configurable caption/speech filters. The popup exposes all four modes directly under **Look for**, rather than hiding them in a closed disclosure. Narrated candidates remain candidates for audio review, not verified narration.

`mode:'any'` represents no selected Look for preset and is the default for new settings. It does not require credits, narration, or keywords. Count, account, duplicate, caption and speech filters still apply as selected. Existing stored modes are preserved. Clear or activating the selected mode again saves `any`; selecting another preset reapplies that preset. Clearing `credits-any` unlocks the caption control while keeping its current `off` choice. For compatibility with the existing engine, unrestricted discovery uses the existing count-qualified `narrated` worker phase and discovery metadata; this metadata does not assert verified narration. User-facing unrestricted match/start messages must not claim narration is required.
