# Codebase audit — October 30, 2026

The audit covered first-party runtime code, entry points, dependencies, startup/build tooling, tests and current documentation. Three parallel specialists examined security, performance and unused code; the coordinating reviewer approved changes, reviewed the patches and reran the combined checks. Existing work in the checkout, the lime theme, Library records and saved Concat projects were preserved.

## Fixed findings

| Finding | Change and evidence |
| --- | --- |
| Crafted media could make local probes request remote URLs | A DASH document disguised as a recording, or an MP4/MOV/M4V file with a matching initial signature, triggered a request to an isolated loopback server. Protocol restrictions alone did not stop the installed FFmpeg's manifest demuxer. Probing, normalization and video thumbnails now also restrict input demuxers to supported ordinary media containers; reference recordings explicitly select their declared container. Real decoder regressions reject these files with no HTTP requests or orphaned uploads. This required importing malicious media or a trusted local API caller; it was not a demonstrated remote-browser authentication bypass. |
| Failed reference uploads could leave files or partial database records | Voice reference/profile creation now commits atomically. Decoder, timeout and registration failures clean the file; expected decoder errors return a useful 400 response. Six real recording formats are tested and retained byte-for-byte. |
| Library and Studio could download the same clip concurrently | Both callers use one atomic download claim. Studio waits outside database transactions for the existing owner, validates the resulting source, and reports failure/deletion. A 30-minute wait limit leaves the owning download running for a later retry. Tests cover both request orders and prove there is only one downloader. |
| Transcription and extraction duplicate checks raced | Active-job check and creation now share a writer transaction. Concurrent requests queue one job and return the existing HTTP 409 error to the duplicate. Failure permits a later retry. Provider calls and media work remain outside the transaction. |
| Queued thumbnails could occupy the default request-worker pool | The async thumbnail route admits at most three lookups before borrowing workers. Existing cache responses and missing-cover behavior remain; unrelated API work can use the remaining pool. |
| Enrichment opened a database connection for every requested clip | One parameterized query loads the batch, then reconstructs request order. Missing IDs still fail before provider requests; duplicate IDs and remote batching retain their behavior. |
| Startup could keep stale packages after a lockfile update | Startup compares manifests, installed lock metadata, package versions and command binaries. It reinstalls mismatched/incomplete trees with `npm ci`, including development tools and platform optionals even under production npm settings. Matching installs are reused. Failures stop startup before building or launching the engine. |

Security regressions live in [media upload tests](../engine/core/tests/test_media_security.py) and [voice reference tests](../engine/ai/test_voice_security.py). Concurrency regressions cover [downloads](../engine/core/tests/test_download_coordination.py), [jobs](../engine/core/tests/test_job_coordination.py), [thumbnails](../engine/core/tests/test_thumbnails.py), and [enrichment](../engine/core/tests/test_enrichment.py). Startup checks are covered by [20 isolated fixtures](../extension/tests/node-setup.test.mjs).

## Dependency changes

The initial advisory scans flagged two dashboard packages and four packages in the installed Python environment. The dashboard now uses Vite 6.4.5 and source-map-js 1.2.2. The environment was updated to Pillow 13.0.0, certifi 2026.10.23, pip 26.2.2 and the already-installed optional tool uv 0.13.6; uv was not added as an application dependency.

Runtime requirements now exclude known-vulnerable older releases of Pillow, certifi, Starlette, AnyIO, python-multipart, python-dotenv and yt-dlp. The new directly used AnyIO limiter also needs an import-safe adapter: isolated checks showed 4.0/4.1 fail application import outside an async context and 4.2 succeeds. The declared floor is higher, 4.14.2, to include subsequent security fixes. The updated requirement floors support the existing Python 3.11 minimum.

Final scans reported **zero known advisories across all three npm projects and the 47 installed Python distributions**. `pip check` passed and the final requirements resolved without further installed-package changes. These results concern the scanned package versions and advisory data available on the audit date.

## Measured performance

The coordinator ran [the retained benchmark](../scripts/benchmark_engine.py) on Linux with Python 3.14.8, SQLite 3.51.2 and eight logical CPUs. It uses a temporary 5,000-clip database and synthetic thumbnail blocking, with no real provider requests, models or native editor.

| Scenario | Previous behavior | Updated behavior |
| --- | --- | --- |
| Local reads for a 100-clip enrichment batch, median of 15 paired samples | 100 connections; 40.974 ms | 1 connection; 2.480 ms |
| 40 thumbnail requests held by a synthetic slow lookup | 40 default workers occupied | At most 3 occupied |
| Unrelated worker dispatch during that injected thumbnail hold | 203.004 ms; blocked until release | 0.151 ms; completed before release |
| Concurrent Library/Studio acquisition of one clip | Two download jobs could run | One shared download job |

These are measurements of local work and injected contention, not whole-workflow speed claims. Network time, OCR/model inference, browser connection limits and Concat rendering can still dominate. Earlier paired runs varied around 35–43 ms versus 2.3–2.7 ms for the enrichment stage.

Reproduce the bounded local measurements with:

```bash
.venv/bin/python scripts/benchmark_engine.py
```

## Cleanup decisions

Removed obsolete card-action CSS, duplicate selection/Scout rules, unreachable terminal progress styles, unused Studio text styles and old progress-result note rendering. Corrected the extension guide's packaged dashboard path and included the upstream Source Serif 4 and Geist Mono license notices.

Entry-point tracing found all nine dashboard modules and eight extension modules reachable, and every extension message handler had a production sender. Retained AI/YouTube routes, media helpers, explicit setup commands, optional models, fixtures and historical records serve supported or documented purposes. No whole module or package was deleted without evidence. Font subsets use unicode ranges and the italic font is part of the existing design contract.

Bandit's SQL warnings were reviewed against fixed/allowlisted identifiers and bound values; flagged network calls used fixed service endpoints or validated IDs. Vulture's unused arguments were callback/classmethod signatures or intentional cache-key inputs. These findings were not treated as confirmed vulnerabilities or a reason to delete working behavior.

## Validation and limits

- Backend: **400 passed, 5 skipped**. The skips were two opt-in native Concat checks and three unavailable local speech/model checks. One existing Starlette/httpx test-client deprecation warning remains.
- Extension unit and startup fixtures: **93 passed**.
- Dashboard: **23 browser tests passed**, including desktop/mobile, light/dark themes, native launch status, large-Library selection and quiet polling.
- Dashboard app/test type checks and both production builds passed.
- Python lint/format, repository formatting, package consistency and whitespace checks passed.
- The unpacked MV3 extension and YouTube/Instagram parsing fixtures were checked after the build.

Windows startup received static review and platform-oriented fixtures, not execution on Windows. The actual environment was Python 3.14.8; Python 3.11 compatibility was checked through declared package requirements and code compatibility, not a second interpreter run. FFmpeg exercised real generated media; ffprobe branches used mocks because a separate executable was unavailable. Live account authorization/publishing, optional model inference, native editing/export, OS packages and third-party native binaries were not exhaustively audited.

Durable Library revision caching, server pagination, persistent model workers and a global media-job scheduler remain separate changes. They were not introduced without the broader lifecycle and compatibility work they require.
