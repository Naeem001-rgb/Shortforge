# Studio UI reconnaissance

Date: 2026-10-02. Scope: read-only source inspection and official-site research; no feature implementation. `docs/editor/TODO.md`, `PROGRESS.md`, and `DECISIONS.md` did not exist when this task started. Impeccable `SKILL.md`, `new-work.md`, and `operate.md` were read; the lead ran the session context command. The user's precise editor brief establishes the direction: an operational, familiar editing workspace in dark graphite with one vivid accent.

## What is real

- The dashboard uses React 19, strict TypeScript, Vite 6, plain scoped CSS, Lucide, and local Inter. The extension is a separate TypeScript/esbuild application. Retain one UI framework.
- `dashboard/src/studio/Studio.tsx` hosts project fetching, all jobs, history, autosave, file input, permission UI, and four asset tabs: Media, Audio, Text, Motion. It renders `EditorPreview`, `EditorTimeline`, `EditorInspector`, and `EditorTemplates`.
- `editorModel.ts` contains a version-1 project of `items`, numeric tracks, video/audio/text kinds, transform/keyframes, text styling, 24 animation entries including None, and a 20-transition catalogue excluding None. This is usable migration material, not the requested complete contract.
- Preview is HTML video/audio plus DOM/CSS text/layer composition with Web Audio gains. Export is a different Python/FFmpeg renderer. Existing source comments claiming identical output should not be accepted as pixel-parity evidence.
- History currently retains 80 states, project commits reject more than 100 items, and the timeline UI caps adding tracks at eight. All conflict with requested P0 limits.
- Timeline already has pointer-driven move/trim, snaps, per-clip waveform rendering, split/duplicate/delete, zoom, keyframe diamonds, and transition readouts. It lacks filmstrip thumbnails and direct keyframe retiming. Preserve useful math and regression coverage while replacing the shell.
- The screenshot's empty editor is also an integration failure: scouting items usually have no source media; the source fetch action requires a separate permission form and manual “Prepare source video” button. Import itself is disabled for inspiration projects. Library grid buttons say “View inspiration” for these items, although the detail modal has “Open in Studio.” Merely changing CSS will reproduce the empty timeline.
- `dashboard/src/theme/editor.css` uses fixed 248/254px side columns, 12px base type, 11px tab labels, 29px icons and `height: clamp(310px, calc(100dvh - 464px), 760px)`. This wastes height, clips the four-tab strip, and makes the canvas small. Two stacked project/action rows duplicate hierarchy.
- Existing tests: Playwright `editor.spec.ts`, `editor-lifecycle.spec.ts`, `workspace.spec.ts`, `library-layout.spec.ts`; Python engine tests. Tests create real FFmpeg media, use an isolated engine and dashboard on 8788/5174, and inspect exported files. Existing screenshot tests cover desktop and mobile but do not prove new brief compliance. No tests were run in this bounded recon task.

## Recommended replacement

Use a full-height workspace with a compact 56px topbar, a genuine asset/tool rail, expanded bin, large center player, a contextual inspector, and a resizable bottom timeline. At 1440×900, target roughly 64px rail + 268px bin + flexible 750px player + 300px inspector; timeline roughly 240px high. Use CSS grid `minmax(0, 1fr)` for the center and explicit draggable splitters. Collapse bin or inspector through visible buttons; never squeeze nine tabs into 240px.

1. **Topbar:** a small ShortForge mark, Library return, editable project title, discreet saved state; undo/redo; ratio/resolution control; one strong Export button. Recent projects belong in the project menu. Separate title from file identity internally so renaming is safe.
2. **Tool rail and asset bin:** icon plus readable label for Media, Audio, Text, Captions, Stickers, Effects, Transitions, Filters, Templates. A panel heading and search/filter row precede actual media or preset previews. Display real thumbnails, duration, source and selected state. Do not manufacture sample assets as if they were imported footage.
3. **Player:** the source should appear automatically when opening from Library, with real fetch/decode progress and recoverable failures. Keep a neutral graphite stage, maximal portrait canvas, selection bounds/handles, center guides and safe-zone toggle. Transport includes timecode, previous/next frame, play, fit zoom and monitor volume.
4. **Inspector:** selected-video tabs Video / Audio / Speed / Animation; selected-text tabs Text / Style / Animation. Use labeled sections, sliders paired with precise inputs, and diamonds beside animatable properties. Keep detached-audio and mute actions easy to find. Defaults should show canvas and project settings, not a blank generic “Select a clip” block.
5. **Timeline:** filmstrip-led video, waveform-led audio, legible caption segments; sticky track labels with lock/hide/mute; fit-to-view, snap and magnetic-track controls together; visible playhead triangle and time ruler. Selection uses a bright outline and handles. Active editing receives most visual contrast.
6. **Caption browser:** show large original typographic swatches and a few useful categories (Bold / Clean / Karaoke / Expressive), with a selected style visibly reflected in preview. Separate transcript editing from style browsing through tabs. Label TTS/cloud transcription network actions plainly.
7. **Audio panel:** a clear three-way choice Record / Generate / Import, then the controls needed for the selected flow. Narration on a voiceover track and source audio on a separate track make replacement understandable. A burned-in caption is video pixels, not a removable subtitle track; offer crop/cover/region treatment honestly rather than promising perfect removal.

## Proposed visual tokens

Extend the existing token system with editor-scoped neutral surface tokens. The current dashboard violet can remain the shared accent to avoid a second competing brand; choose a saturated violet action and a lighter matching selection tint. Suggested neutral values: stage `#101115`, app `#15161b`, panel `#1b1d23`, raised `#242730`, border `#30343e`, text `#f3f4f7`, muted `#9fa6b5`. Confirm contrast in browser. Use 10–12px panel corners and 8px compact inputs, local Inter 12/13/14/16px with tabular numbers, 32–36px icon hit targets, 180ms ease interactions and reduced-motion support. Keep vibrant caption examples inside content, not across the surrounding chrome.

The visual ambition should come from excellent media presentation, proportion, strong selection feedback and polished direct manipulation. Avoid decorative gradients, slogans, dashboard stat cards, mock projects, unnecessary banners, or a second hero section inside the editor.

## Architecture and verification recommendations

- Replace the workspace markup/CSS decisively while isolating model/media/export migrations. Move orchestration out of the monolithic Studio into project lifecycle, jobs and editor actions hooks. A coordinator owns project state; panels receive typed commands, not their own parallel project models.
- Introduce explicit track objects, source metadata and caption word timestamps in a migrated versioned schema before adding track controls or unlimited lanes. UI-only controls would otherwise be dead or unsaved.
- One render contract is essential before claiming WYSIWYG. Choose deliberately whether the first supported export remains the local Python engine; the requested browser-only WebCodecs path is a significant architectural change, not styling work.
- Every asset entry needs loading, ready, missing/relink, failed/retry and selected states. Fetch-on-open needs deduplication and cancellation so route changes cannot put one clip into another project.
- Use existing Playwright fixture machinery to capture a populated 30–60 second project at 1440×900 and 1920×1080, plus a narrow layout that collapses panels rather than shrinking controls. Measure rather than assume timing, frame rate, export speed or sync.
- Acceptance for shell task: all nine categories reachable, tab navigation visible, no horizontal overflow or clipped headings, usable portrait canvas, panel resize/collapse survives reload, inspector tracks selection, real loading/error states, and keyboard-accessible focus. Acceptance for Library entry: click Edit once, full-tab editor opens, existing source or download job populates both media bin and timeline without further technical choices.
- Independent critique must use a real media project, not only the empty state; compare preview and export frames, exercise detach/mute/replacement audio, and verify route/reload persistence. Existing tests are starting coverage and may need semantic-selector updates as the UI changes.
