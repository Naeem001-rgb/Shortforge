# Decisions

- **D01 / authority**: The latest master brief supersedes the old no-AI-workflow/no-upload/mandatory-rights-lock directions. Unknown source status is preserved and flagged in credits; no automatic ownership assertion is made.
- **D02 / reuse**: Keep React/Vite and local Python services. A destructive deletion of tested media services would lose working extraction, speech and export. Replace the interface and upgrade modules in isolation instead.
- **D03 / delivery**: Build a full-tab, URL-addressable Studio; package it in the extension if the existing Vite API routing can be made explicit. Long jobs stay out of the extension service worker.
- **D04 / design**: Operate mode. User pinned a familiar professional editor, dark graphite, one accent and panel/timeline topology. Impeccable concept seed 5ef70c64 ran; its index/challengers cannot override the pinned direction. No additional product-direction approval is needed. Code-led build; supplied screenshot is an anti-reference, not a design to reproduce. Keep violet identity, use neutral graphite instead of tinted flat gray and provide a spacious, useful stage and clear active states.
- **D05 / verification**: No demo footage is inserted into real libraries. Automated tests may generate labeled synthetic fixtures. Final acceptance additionally needs a real 30–60 second licensed/sample clip and measured export results.
- **D06 / removal**: Original audio can be muted/detached. Existing local separation may isolate vocals approximately. Burned-in captions are pixels, so offer crop/cover/blur with honest naming; separately imported captions are editable/deletable. Do not advertise perfect removal.
- **D07 / security**: Keep provider secrets out of project JSON and logs. Existing local server secret storage remains a compatibility implementation; extension-only key storage requires explicit integration work and cannot be claimed before tested.
- **D08 / tracking**: Each task gets up to two independent critique rounds. Failed P0 caps score at 6, failing checks at 5. After round two, close failures into KNOWN_ISSUES without describing them as complete. Full-product acceptance is separate from task closure.
- **D09 / additive contract**: Lead added optional document `tracks/markers/script/name`; item `caption_words` (word times relative to clip start), `caption_style/font_family/reverse/freeze_at/flip_x/flip_y/crop/adjustments/animation_loop/group_id/blend_mode/mask/chroma_key/conceal/audio_role/ducking`; keyframe `values` numeric property map, `bezier` and hold/spring/bounce/cubic-bezier easing. Crop and conceal values are 0–100 canvas/media percentages. Freeze time is source seconds. Track flags persist in document. Backend fields default and preserve older projects. No new field may be advertised as working until both preview/export implement it.
- **D10 / dependencies**: Mediabunny now uses MPL-2.0 and is excluded by the owner's permissive-only requirement. Evaluate the MIT mp4-muxer compatibility package with pinned version and codec tests, recording its deprecation; do not silently adopt MPL. Existing FFmpeg binary reports GPL/version3; it remains a separately installed local executable, not redistributed extension code.
- **D11 / rendering implementation**: Shared `renderFrame()` composites measured caption textures and video on Canvas2D, with WebGL2 shaders for all 20 transition recipes and video color/effect processing. This keeps text layout identical between preview/export and has an honest Canvas fallback. Browser frame stepping uses WebCodecs encode and a bounded H.264 decoder where supported; unsupported source layouts use browser seeking. MP4Box 2.4.1 is BSD-3-Clause. A single final Opus encoder flush is essential: repeated flushes inserted measurable silence and were removed after a 30-second regression.
- **D12 / animation contract**: `Keyframe.preset` records the original in/out/loop recipe for editable sampled keys; `TimelineItem.animation_labels` keeps the selected recipe name. Applying a recipe compiles its combined transforms and blur into ordinary numeric keys. Maximum stored keys is 5,000 per clip; keyframe sorting is cached, interpolation uses binary search. Old raw animation fields remain a migration/compatibility input.
- **D13 / local storage**: Existing local-engine SQLite/media files remain authoritative. Browser recovery also uses IndexedDB. Normalized export sources are streamed to OPFS, with direct-source fallback when the browser has no storage or available quota. Relinking imports a replacement as a new asset and retains timeline edits within that replacement's bounds. No original source file is modified.
- **D14 / original audio assets**: Three 24-second synth beds and six effects are generated by `scripts/generate-studio-audio.py`, with no external samples/compositions. They are supplied under CC0 with the recipe. They are imported as normal editable audio and music is initially ducked under voiceover.
- **D15 / review rules**: Round 1 independently scored the whole product 5/10 and enumerated material gaps; see critiques/Q02-round1.md. The correction batch addresses real compositing/geometry/project management defects, adds missing source recovery, and updates tests for authorized navigation changes. Round 2 must be a different reviewer; failures are closed and recorded, never relabeled as passing. Rate-limited agent sessions resume from committed work instead of repeating recon.
- **D16 / replaceable animations**: Optional `animation_base_keyframes` retains authored motion before a preset is compiled. Replacing/removing presets restores that motion; trims rebase both stored and visible keys. Convert to manual keys explicitly keeps the rendered motion and releases recipe metadata. This is an additive version-1 field with validated bounds.
- **D17 / stateless recovery**: Disk files, Git commits, tests and this ledger are the only recovery source. Provider response chains are never reused. The live backend observed on October 3 had started before the rights-lock removal, explaining the obsolete screenshot warning; restart after verified integration, preserving local data.
